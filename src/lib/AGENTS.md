# src/lib rules

- MiMo order entry uses a client-safe cent-based domain module shared by UI and authenticated server functions; immutable JSON document versions hold items, quotes, volumes and payment snapshots so commercial edits never overwrite historical proposals.
- The MiMo dashboard computes indicators in one pure client-safe module from a lead cohort (entered in the period) and Meta rows fully inside the same period. Company-wide data is restricted to administrador/gestor/marketing; vendedores receive only their currently assigned leads, filtered by the authenticated actor on the server with caller-scoped RLS, and no company Meta metrics. Keep cohort periods consistent and personal history isolated from colleagues.
- MiMo weekly reports and CSV exports reuse the dashboard's pure cohort filters and are produced client-side only from rows an admin/gestor-checked server function returned; CSV cells are formula-neutralized and exclude phones/internal IDs, so reports never diverge from the dashboard or leak data.
- A generic request for the MiMo marketing team is only a hint: deterministic code asks the subject, suspends resale reminders meanwhile and outranks the source creative; only an explicit or confirmed influence partnership without concurrent commercial intent sends the official influencer form, and the worker final authorization disqualifies it (sem_perfil) atomically; any reservation of a non-pending lead persistently blocks and cancels its automatic follow-ups.
- MiMo agent commercial questions are answered only by approved policy or the existing handoff, never replaced by triage questions; automatic follow-ups are suppressed in the worker while the latest customer block still has an unanswered commercial question, so reminders never bury a pending answer.
- MiMo agent source-creative subject comes only from provider-attested ad metadata (title/description) stored on the inbound event, read company/lead-scoped by the worker; it sets the opening subject and prompt context but explicit lead statements always win, and missing or ambiguous metadata never yields an inferred creative.
- MiMo agent automatic follow-ups wait 1h then 3h total of silence, both anchored on the same last inbound customer message (silencio_em); the worker rechecks that anchor before sending so legacy or retried rows can never send early.
- Explicit own-consumption purchases receive the MiMo agent's published retail offer. Only a reviewed URL with a coupon or an explicitly automatic discount may be sent. An unavailable retail offer goes to the team without resale qualification, and resale reminders stay suppressed for a personal purchase.
- Monthly sales statements are private company-scoped imports for active MiMo administrators and managers. Keep the imported sales snapshot in the RLS-protected table. Store approved edits to the monthly target and daily actuals as separate company-scoped overrides. Allocate the target across registered working days in integer cents and calculate each period from its totals, including actual sales on holidays.
- MiMo jellies (catalog items named Geleia, type outro, not gifts) ship only in the exclusive GEL box, up to its jelly capacity per volume, never mixed; configs lacking GEL get it appended (an existing GEL is reused), and weight is the real item weight sum with no presumed tare.
- MiMo temperinhos (catalog items named Temperinho, type outro, not gifts) are packed only in an active configured box with a temperinho capacity (largest one wins), up to that capacity per volume, never mixed; the suggested volume carries the tipoDaCaixa snapshot the server compares by JSON. With no such box they fall back to an unverified G volume, never a presumed fit.
- The MiMo lider_marketing role has exactly the marketing scope (ehMarketing helper in code; same enum lists in SQL/RLS); every marketing allow or deny check must include both, so the role never gains or bypasses access.
- MiMo sales per seller (orders panel) is for administrador/gestor/administrativo: orders come from the caller-scoped safe view (RLS), grouped by documento.responsavelId (admins/managers included); drafts and cancellations never count as sales. Administrativo gets owner names through a server read limited to active administrador/gestor/vendedor names after its membership is verified.
- MiMo order billing data (documento.faturamento) is trimmed free text defaulting to empty, read with the same scope as the other customer fields and kept out of assinaturaFrete so it never invalidates freight quotes. Boleto terms are 1–6 unique canonical day strings from 1 to 180 kept in ascending order; 14/21/28/35/42 are only shortcuts, and no database rule depends on them.
